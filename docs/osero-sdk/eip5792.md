# Execute plans with EIP-5792

Import `@osero/client/eip5792` to submit the pending steps of an `ExecutionPlan` through one
`wallet_sendCalls` request. The wallet must confirm the complete batch atomically.

The adapter also batches plans whose execution requirement is `sequential`. Plan order still
defines call order. A capable wallet executes all pending calls in one atomic bundle.

## Check wallet support

Use `supportsAtomicBatch` to decide whether to show atomic batch UI. The probe returns `false` for
a disconnected wallet, a failed capability request, malformed capabilities, or unsupported atomic
execution. It never throws.

```ts
import { supportsAtomicBatch } from '@osero/client/eip5792';

const canBatch = await supportsAtomicBatch(walletClient);
```

Treat the result as a UI hint. `sendWith` probes again before execution because wallet capabilities
can change after rendering.

## Send a plan

```ts
import { sendWith } from '@osero/client/eip5792';

if (prepared.isErr()) throw prepared.error;

const result = await sendWith(walletClient, prepared.value.plan, {
  confirmations: 2,
  confirmationTimeoutMs: 120_000,
  onProgress(progress) {
    console.log(progress.type);
  },
});

if (result.isErr()) {
  console.error(result.error.code, result.error.toJSON());
} else {
  console.log(result.value.txHash);
  console.log(result.value.transactions);
}
```

One wallet transaction can confirm several logical plan steps. Each `ConfirmedTransaction` keeps
its plan step identity and uses the terminal transaction receipt hash.

## Understand mainnet multi-step execution

Ethereum mainnet sUSDS preparation can produce approve, mint USDS, approve, and deposit steps. The
adapter sends the pending steps as one atomic bundle. This is safe because `prepareSwap` bakes the
quoted amounts and bounds into each step's calldata before execution.

## Control sequential fallback

Atomic capability discovery can fail or report no support. By default, the adapter then uses the
standard viem executor and sends each pending transaction sequentially.

Set `fallbackToSequential: false` when the application requires one atomic wallet action:

```ts
const result = await sendWith(walletClient, prepared.value.plan, {
  fallbackToSequential: false,
});
```

The adapter returns `UnsupportedCapabilityError` without sending a transaction when fallback is
disabled. A plan whose `requirements.execution` is `atomic-batch` also rejects an unsupported
wallet and never falls back.
